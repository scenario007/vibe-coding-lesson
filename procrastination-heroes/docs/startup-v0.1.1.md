# v0.1.1：关闭启动窗口后网页无法连接

修复日期：2026-10-25。

## 原因与复现

用户双击 Start.command 后，后端与 PostgreSQL 正常运行，前端进程却已退出。实际检查结果为：8088 健康检查 HTTP 200，54329 可连接，5173 连接被拒绝，frontend.pid 对应进程不存在。

Vite 8 在交互终端输入结束时会关闭服务。原启动器虽然创建了独立进程会话，仍让前端继承终端输入；关闭启动窗口就可能触发退出。旧版只有从非交互命令环境启动的验证，遗漏了真实终端关闭的情况。

在独立 5174 端口以伪终端启动真实 Vite，关闭终端前 HTTP 200，关闭后两秒连接被拒绝，npm 正常退出（退出码 0）。这与用户现象一致。

## 修复

- 后台服务的标准输入明确连接到空设备，断开与启动终端的关联。
- 仅在前端子进程设置 `CI=true`，关闭 Vite 的终端输入退出行为；不修改全局环境或业务代码。
- 启动器等待就绪时检查新进程的退出状态，启动失败立即指出对应日志位置。
- 就绪提示说明可关闭启动窗口；README 补充操作和回归验证入口。

## 验证方式

`python3 scripts/launcher_test.py` 使用真实终端和真实 Vite、临时端口与临时日志，依次验证启动器退出、关闭终端后至少 5 秒 HTTP 仍为 200、测试进程可完整停止。它调用实际的 dev.spawn，不复制一套启动实现。测试不会启动模型调用、修改数据库或关闭项目服务。

实际服务另外检查前端页面、Vite 转发的后端健康检查、重复启动和完整停止再启动。数据库存档保留。

本次结果：专项回归通过；完整停止再启动后关闭伪终端，5173 网页、5173/api/health 转发及 8088/api/health 连续 5 秒均为 HTTP 200；重复启动正确复用已有服务。Python 编译检查、两个 .command 脚本的 zsh 语法检查和 Git 空白检查通过。验证后保留实际服务运行，便于用户直接刷新网页。
